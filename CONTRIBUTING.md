# Работа над Garasu

Garasu хранит публичные конфигурации и наборы маршрутизации, а не данные VPN-пользователей.

## Ветки и выпуск

- **dev** — разработка, регрессионные тесты и аудит.
- **main** — проверенный выпуск; изменения публикуются только после quality gate.
- Новые постоянные ветки и GitHub Actions не используются.
- Пути clients/ и install/ нельзя изменять без плана миграции уже опубликованных ссылок.

## Проверка

```bash
python3 -m pip install 'PyYAML>=6,<7'
python3 scripts/qa.py --branch main
```

При наличии локального Mihomo:

```bash
python3 scripts/qa.py --branch main --core /path/to/mihomo
```

Офлайн-проверка сверяет 62 файла манифеста, 13 MRS, ссылки, SSR, Python-тесты, безопасность и отчёты качества. Нативная проверка пересобирает MRS и проверяет конфигурации с синтетическими узлами. Она не подключается к реальным VPN-нодам.

После переноса проверенного релиза в main:

```bash
python3 scripts/probe_release_assets.py --branch main
```

В dev тестируется **кандидат для main**: ссылки на стабильные опубликованные правила остаются на main до публикации.

## Правила данных

1. Изучайте [источники и права](SOURCES.md) перед добавлением наборов.
2. Фиксируйте одну ревизию upstream, сверяйте SHA-256, размеры и пороги количества записей.
3. После изменения .list / .cidr пересобирайте MRS, не выпускайте устаревшие бинарники.
4. Не публикуйте личные subscription URL, UUID клиентов, приватные ключи, токены и файлы .env.
5. Перед изменением публичных шаблонов сверяйте существующие SSR, User-Agent и имена шаблонов в панели.

Коммит в GitHub **не изменяет Remnawave**. Откат, проверка публикации и тестовый выпуск описаны в [чек-листе](docs/release-checklist.md).
