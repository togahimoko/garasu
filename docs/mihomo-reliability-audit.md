# Garasu / Mihomo — диагностический прогон

## Обнаруженная причина риска

В текущей *рабочей* Mihomo-подписке Remnawave нет явного `mixed-port`.
Поэтому использование HTTP/SOCKS без TUN зависит от того, какой порт
добавляет и включает сам клиент. Некоторые клиенты управляют этим полем
отдельно. Отсутствие его в YAML **не доказывает**, что порт не слушает:
нужен эффективный конфиг и проверка слушателя.

Группа `Garasu` разрешает выбирать `DIRECT`, а `profile.store-selected:
true` может сохранять это решение. Если выбран `DIRECT`, то `MATCH,Garasu`
не проксирует зарубежные сайты. Если `Garasu Auto` не выбран, его
автопроверки могут не запускаться из-за стандартного `lazy: true`.
Старый CI проверял только YAML; он не проверял, что локальный прокси
принимает HTTP-запросы и выводит успешную задержку через узел.

## Исправление только для canary

`clients/canary/mihomo-remnawave.yaml`:

- включает `mixed-port: 7897` для HTTP и SOCKS5;
- в группе Garasu оставляет только `Garasu Auto`, без обхода через DIRECT;
- сбрасывает сохранение ручного выбора `store-selected: false`;
- включает проверки задержки `lazy: false`, таймаут 8000 мс;
- сохраняет правила DIRECT для российских сайтов и локальной сети;
- **не включает TUN автоматически**;
- не содержит узлов или ключей пользователя.

Важно: в Clash Verge Rev (и других оболочках) порт System Proxy должен
совпадать с реальным `mixed-port`. Значение `7897` — обычный вариант,
но если клиент слушает другой порт, не подменяйте его вслепую.

## Проверка именно твоего Mac, без подписки и ключей

Скачать из GitHub `scripts/diagnose_mihomo.py`, запустить:

```bash
python3 scripts/diagnose_mihomo.py
python3 scripts/diagnose_mihomo.py --probe-net
```

Если контроллер на другом локальном порту:

```bash
python3 scripts/diagnose_mihomo.py --controller-port 9097 --mixed-port 7897 --probe-net
```

Если контроллер запрашивает секрет, задать его локально в переменной
`GARASU_MIHOMO_API_SECRET` (не отправлять секрет в чат).

Диагностика не переключает серверы и не меняет подписку. Возвращает
только обезличенный блок `SAFE MIHOMO REPORT`: слушатели, число узлов
в авто-группе, режим, TUN, признаки сохранённого DIRECT и HTTP-ответ.

`NO_MIXED_PORT` — нет HTTP/SOCKS listener в активном конфиге. 
`LOCAL_PROXY_NOT_LISTENING` — целевой порт не слушает.
`GARASU_DIRECT_SELECTED` — выбран прямой выход.
`AUTO_GROUP_EMPTY` — в автоматической группе нет ни одного узла.
`CONTROLLER_NOT_ACCESSIBLE` — необходимо проверить порт API/секрет.

## Проверка на реальных серверах

Сначала сохранить текущий рабочий профиль и импортировать canary
отдельно в Remnawave. Не заменять действующий Mihomo template и не
обновлять общие Subscription Response Rules.

На Mac выключить TUN **только для отдельного теста**, оставив
HTTP/System Proxy, и проверить: есть listener, запрос через него
выполняется, задержки узлов отображаются, YouTube идёт через VPN,
а нужные российские ресурсы DIRECT. Вернуть настройки после теста.

Тесты GitHub используют синтетический HTTP-узел, а не VLESS/Reality.
Реальную достижимость ноды, DNS из РФ, текущую версию клиента и
маршрут Remnawave → Россия → Чехия можно подтвердить только на
авторизованном устройстве.

### Важные ограничители

- Проверка URL-Test использует `https://cp.cloudflare.com/generate_204`,
  рекомендованный Remnawave. Если узел работает, а задержка не
  измеряется, отдельно проверить другой HTTPS endpoint и версию Mihomo.
- В некоторых версиях ядра локальные тесты короче 1 мс могут давать
  статус 503 — тестовая система специально добавляет небольшую
  задержку синтетическому прокси, чтобы не давать ложных результатов.
- Нельзя считать проверку YAML-парсера доказательством работы прокси.
