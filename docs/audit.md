1. `release/` содержит один актуальный набор по клиентам.
2. `release/mihomo/.mrs/` содержит ровно 13 бинарных файлов и контрольный манифест.
3. `rules/` и `geo/` оставлены: эти форматы нужны другим ядрам и уже опубликованы.
4. Удалены дублирующие стадии `clients/canary`, `clients/unified`, `clients/experimental`, `rules/unified`, `policy/unified-*`.
5. Удалены устаревшие планы, альтернативные SSR-сборщики, старые тесты и workflows.
6. Новые тесты проверяют актуальные SSR и нативные профили, а не несуществующие экспериментальные файлы.
7. Технические домены в списках правил (например, сервисы AI) сохранены как функциональные данные. История Git не переписывалась: это нарушило бы воспроизводимость и сторонние ссылки.

## Открытые риски — не считать выпуск завершённым

**Высокий приоритет**

- **Миграция из Remnawave не проверена.** Не сверены фактические SRR, имена сохранённых шаблонов и клиентские User-Agent у платных пользователей. Нельзя переключать полный `srr.json` без проверки.
- **Профили релиза ссылаются на ветку `staging`.** Перед выпуском на `main` эти URL должны быть проверены и закреплены за правильной веткой/ревизией. Удаление `staging` до миграции оборвёт обновления.
- **Сборка MRS не автоматизирована.** Клиент обновляет бинарники по URL, но новые бинарники не появляются после редактирования исходного `.list` автоматически. GitHub Actions удалены; требуется отдельный согласованный механизм обновления.

**Средний приоритет**

- Не выполнен нативный импорт в INCY, Happ, Shadowrocket, Stash и sing-box на устройствах. Статическая проверка JSON не равна успешному запуску клиента.
- Не подтверждён холодный старт без кеша на ограниченных сетях, в том числе доступность GitHub Raw по DIRECT.
- Плавание TCP-доступности Steal через конкретного провайдера не решается рефакторингом репозитория. Обход IP/маршрутных ограничений нельзя гарантировать одними правилами.
- Старые `clients/` и `install/` технически необходимы до миграции: полностью убрать дублирующую доставку сейчас нельзя без риска для подписчиков.

## Критерии переноса в основную ветку

1. Проверить действующие SRR, сохранённые шаблоны Remnawave и их реальное использование.
2. Перевести тестового подписчика на `release/`, проверить персональный состав узлов, DNS, маршруты и автообновление.
3. Проверить всё семейство клиентов нативно, включая переключение Wi-Fi/мобильной сети и недоступность VPN.
4. Решить обновление MRS и источников без нежелательных GitHub Actions.
5. Обновить ссылки с `staging` на утверждённый адрес релиза; повторить тесты и только затем переносить изменения в `main`.

Статический аудит репозитория и тестовый runtime завершены; эксплуатационный аудит всех реальных клиентов и панели Remnawave остаётся отдельным обязательным этапом.
