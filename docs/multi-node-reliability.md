# Garasu — многонодовая архитектура и проверка отказоустойчивости

## Обязательный контракт

Garasu **не ограничивает количество узлов, стран и протоколов**. Пользователь
может иметь одну, две или много нод; доступный список формирует персональная
подписка Remnawave. Правила маршрутизации отделены от списка нод:

- **DIRECT:** LAN/loopback/локальные DNS, обычные российские ресурсы.
- **PROXY:** заблокированные российские ресурсы, необходимые зарубежные сервисы,
  остальные зарубежные направления, если нет отдельного осознанного исключения.
- **REJECT:** блокируемые правилами рекламные/трекерные ресурсы.
- При нескольких доступных нодах клиент **автоматически выбирает исправную**,
  затем проверяет её с заданной периодичностью и переключается при отказе.
- При отсутствии рабочих нод **PROXY не должен незаметно превращаться в DIRECT**.
  Российский DIRECT и локальная сеть должны оставаться доступными.
- Узлы **не фильтруются по стране, имени, префиксу и протоколу**, если
  это не отдельное сознательное требование пользователя.
- Подписка может меняться (1 → 5 → 2 → 0 → 3 ноды); список не хардкодится.
  Поддержка реального обновления проверяется в конечном приложении.

Абсолютная бесперебойность недостижима: если недоступны все входы, сеть
провайдера или DNS, Garasu не может создать интернет-соединение из ничего.
Цель — быстрый автоматический переход между **рабочими** маршрутами,
правильное поведение при полном отказе и отсутствие скрытых утечек.

## Что реализовано или готовится

| Клиент / формат | Много нод | Автоматический выбор | Ограничения |
|---|---|---|---|
| Mihomo / Clash Verge | `include-all: true` в `Garasu Auto` | `url-test`, tolerance, interval, проверка статуса, отбраковка ошибок | Проверить эффективный конфиг и работу подключений на реальном клиенте |
| Stash | Подписка подставляет узлы в `Garasu` | Canary — `url-test` вместо ручного select | Пустой пул у Stash может стать DIRECT, поэтому в canary добавлен `REJECT`; проверить фактическую инъекцию |
| sing-box | Подписка подставляет список в `outbounds: null` | Стабильный шаблон — **selector** (ручной); эксперимент — `urltest` | Эксперимент **не назначать пользователям**, пока настоящая панель Remnawave не подтвердила инъекцию именно в URLTest |
| Shadowrocket | Импорт серверов отдельно от routing config | Зависит от настройки списка/политики и приложения | Один импорт Garasu не включает автоматически резервирование всех нод |
| INCY / Happ | Персональный список серверов отдельно от правил | Зависит от возможностей клиентского приложения | Проверить реальный импорт и поведение при падении текущей ноды |
| Xray advanced | Возможно несколько outbound через Remnawave advanced injectHosts | Балансировка требует отдельного реального Xray-конфига | Текущий шаблон с `addVirtualHostAsOutbound` **не доказывает автоматическое переключение** |
| Surge/Loon и Quantumult X | Правила не содержат ноды | Внешняя политика клиента | Это наборы правил, не готовые полноценные подписки |

## Автоматические CI проверки

- `tests/test_multinode_subscription.py`: размеры пулов 1, 2, 5, 16 и 32;
  корректный список узлов, автоматические группы, отсутствие встроенного
  DIRECT на VPN-маршрутах, сохранение резервного REJECT при пустой подписке.
- `scripts/smoke_cores.py`: имитация динамического наполнения Remnawave
  без ключей, адресов серверов и личных подписок.
- `scripts/probe_mihomo_runtime.py`: реальное ядро Mihomo с тестовым
  HTTP/TLS-узлом.
- `scripts/probe_mihomo_failover.py`: три искусственных узла; первая и
  вторая ноды работают, третья недоступна. CI отключает первую и проверяет,
  что **реальный Mihomo самостоятельно** переключился на резервную без
  запроса пользователя. Это проверка логики ядра, **не реальных VLESS-узлов**.
- CI с настоящими ядрами проверяет синтаксис и базовую работоспособность,
  **но не** реальную подключаемость конкретных VLESS/REALITY-нод из РФ.

## Обязательная матрица приёмки

1. На тестовом пользователе Remnawave: 1 → 2 → 5 → 1 → 0 → 3 ноды
   без перегенерации правил вручную. Проверить ответ подписки каждой семье
   клиентов (Mihomo, Stash, sing-box, Xray, XRAY_BASE64).
2. У одной ноды искусственно пропадает связь: продолжается работа
   PROXY-направлений через доступную ноду без ручного выбора.
3. Все ноды выключены: PROXY-направления недоступны, но не уходят напрямую;
   DIRECT и LAN продолжают работать.
4. Перезапуск приложения и обновление подписки: не остаётся скрытого
   сохранённого выбора несуществующей ноды.
5. DNS, IPv4, IPv6, UDP, HTTPS, TCP, домашняя сеть; проверять реальный
   исходящий IP и конкретное правило, а не только HTTP-код проверки.
6. Списки маршрутизации доступны при холодном старте и после отказа CDN;
   кэш прошлой валидной версии допускается, недоверенная или битая —
   не должна подменять рабочие правила.
7. Протестировать сети провайдера и мобильного оператора, где будет работать
   продукт, а не только GitHub runner.

## Изоляция

В GitHub **не размещать** личные ссылки подписки, UUID, ключи, SNI,
действительные адреса серверов. Рабочие Remnawave SRR и
`clients/*` production не переключаются без реального приёмочного теста.
