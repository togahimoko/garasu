# Архитектура Garasu

Garasu публикует нативные профили маршрутизации и списки правил для VPN-клиентов. Серверы, ключи и права доступа подписчиков принадлежат Remnawave; GitHub не содержит персональных VLESS-подписок.

## Каталоги

| Путь | Назначение |
| --- | --- |
| `release/` | Актуальные шаблоны по приложениям и правила выдачи Remnawave |
| `release/mihomo/.mrs/` | Бинарные наборы Mihomo/Stash и файл контрольных сумм |
| `rules/` | Исходные категории и нативные экспортные форматы для разных ядер |
| `geo/` | GeoSite и GeoIP для Xray-совместимых клиентов |
| `scripts/` | Обновление источников, проверка качества, диагностика и безопасность |
| `tests/` | Контрактные, функциональные и регрессионные проверки |
| `clients/` | **Совместимость**: старые публичные URL, используемые существующими подписками |
| `install/` | Старые установочные ссылки и манифесты; сохраняются до миграции |
| `reports/` | Результаты аудита наборов правил (генерируемые данные) |

Папки `clients/` и `install/` нельзя удалять до проверки и миграции реальных подключённых клиентов: их URL уже опубликованы, а GitHub Raw не предоставляет перенаправление при удалении файла.

## Форматы

- Mihomo: `release/mihomo/config.yaml` — одна автоматическая группа Garasu (url-test), 35 удалённых бинарных MRS и 2 classical YAML.
- Classic Clash/Premium: `release/clash/config.yaml`, отдельные YAML rule-providers на GitHub и одна автоматическая группа Garasu; MRS и include-all Mihomo здесь не используются.
- Stash: `release/stash/config.yaml` — автоматический url-test и 10 бинарных MRS.
- sing-box: `release/singbox/config.json` — 37 удалённых бинарных SRS.
- INCY/Happ: `release/incy/config.json` и `release/happ/config.json`, нативная политика Xray/geo.
- Shadowrocket: `release/shadowrocket/config.conf`, отдельная политика при сохранении личной подписки.
- Xray JSON: `release/xray/config.json`, опциональный шаблон виртуального хоста.
- Remnawave: один рабочий SSR `release/remnawave/srr.json`; второго тестового профиля нет.

Одного универсального файла для всех ядер нет. Remnawave должен выдавать подходящий формат по клиенту, сохраняя персональные узлы и доступы.

## Маршрутизация

1. Локальная сеть, loopback и приватные адреса идут напрямую.
2. Точные исключения для заблокированных доменов и IP обрабатываются до широких российских DIRECT-правил.
3. По категориям зарубежные сервисы и остальной внешний трафик идут через Garasu.
4. При отсутствии здорового VPN-узла зарубежный трафик не должен незаметно переходить в DIRECT.
5. Холодный запуск ссылочных списков зависит от доступности GitHub или кэша; перед выпуском проверить отсутствие циклической загрузки и отказов DNS.

Группа Garasu автоматически выбирает доступную ноду без переключения маршрутов по сайтам.

## Цепочка данных

Исходные наборы скачивает и проверяет `scripts/refresh.py`; скрипт формирует данные `rules/`, `geo/`, `install/` и отчёт качества. Скрипт `release/mihomo/build.py` компилирует исходные домены и CIDR в настоящие MRS. Контрольные суммы лежат в `release/mihomo/.mrs/manifest.json`.

Обновление исходников требует повторной компиляции MRS/SRS; это выполняется `scripts/build_binary_assets.py` и проверяется до публикации.
