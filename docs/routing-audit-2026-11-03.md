# Аудит маршрутизации Garasu — 3 ноября 2026

Проверен commit `d5c5b908bac93aaa38203ff46574c0fe2b14bbbc`. Это аудит корректности маршрутизации и интеграции клиентов, а не проверка доступности сайтов из сети пользователя. Основные профили и сервер Remnawave не изменялись.

## Вывод

Наборы данных и синтаксис конфигураций проходят существующие проверки, но репозиторий пока не обеспечивает одинаковое поведение всех клиентов. Часть улучшений находится только в canary. Наличие конфигурационного файла не доказывает захват системного трафика, правильную выдачу узлов панелью или доступность выхода из РФ.

Пользователь выбрал: российские ресурсы DIRECT после исключений; зарубежные PROXY; дополнительные зарубежные DIRECT-исключения только явно. Сейчас широкие категории Microsoft, Apple и игр этому не соответствуют.

## Подтверждённые расхождения

### 1. Зарубежный DIRECT шире выбранной политики

`rules/direct.list` содержит широкие зарубежные суффиксы; `rules/games.list` направляется DIRECT. Happ/INCY напрямую подключают geosite:apple, microsoft, steam и другие игровые категории (`clients/happ.json:19`, `clients/incy.json:19`). Также DIRECT применён к geosite:ip-check: api.ipify.org, checkip.amazonaws.com, ifconfig.me. Проверка IP на таком сайте может показывать адрес провайдера при работающем прокси для других сайтов.

Сопоставление скачанных 3 ноября общественных списков с текущим порядком текстовых правил выявило DIRECT-кандидатов:

- itdoginfo GeoBlock: designer.microsoft.com, ntp.msn.com;
- Re:filter community: edge.microsoft.com, mobile.events.data.microsoft.com, rbxcdn.com, roblox.com, software-static.download.prss.microsoft.com, tokenized.play.google.com.

Это подтверждает конфликт политик списков, **не** текущую блокировку каждого имени на любом провайдере. Телеметрию нельзя автоматически объявлять необходимым PROXY только потому, что она есть в общественном списке.

### 2. Разные клиенты принимают разные решения

Stable sing-box не содержит общего правила российских TLD, modern/canary содержит. Stable Shadowrocket использует встроенный GEOIP RU; canary — дополнительные российские суффиксы и собственный ru-ips. Категория geosite:category-ru содержит 1145 доменных записей и не является общим правилом всех .ru/.su. Поэтому правило для произвольного российского домена зависит от клиента и IP.

Happ/INCY используют block-proxy-direct (`clients/happ.json:18`), Xray блокирует рекламу до proxy (`clients/xray-advanced-remnawave.json:24`). В остальных профилях proxy-исключения идут раньше рекламы. В GeoSite есть реальные пересечения: ads.youtube.com, browser-intake-datadoghq.com, o33249.ingest.sentry.io, o33249.ingest.us.sentry.io, openai.qualtrics.com. Приоритет необходимо определить единообразно.

### 3. Xray IPIfNonMatch не классифицирует неизвестный hostname по IP

`clients/xray-advanced-remnawave.json:76` завершает первый проход правил безусловным `network: tcp,udp → proxy`. В `:82` используется IPIfNonMatch. Исходный код закреплённой версии Xray возвращает найденное правило до ветки разрешения DNS. Поэтому неизвестный домен на RU IP уходит в PROXY, не доходя до второй проверки GeoIP. Синтаксическая проверка этого не обнаруживает. Прямо указанный IP — другой случай.

Источник семантики: [Xray v26.10.21 router.go](https://github.com/XTLS/Xray-core/blob/v26.10.21/app/router/router.go#L201). Исправление должно сопровождаться тестом hostname → управляемый DNS → наблюдаемый outbound.

### 4. Системный VPN поддержан не везде

Mihomo-профили не включают TUN; `tests/test_mihomo_proxy_regression.py:39` требует его отсутствия. GUI может добавить TUN, но это отдельная настройка эффективного профиля. Xray advanced содержит только SOCKS/HTTP (`clients/xray-advanced-remnawave.json:85`). Sing-box содержит TUN, но `check` не устанавливает маршруты ОС и не проверяет захват пакетов. В Happ, INCY, Shadowrocket и Stash VPN-интерфейс обеспечивает само приложение.

### 5. DNS и LAN не сведены к единому контракту

Stable sing-box подменяет A/AAAA fake-IP без локальных исключений, а resolver `local` использует публичный UDP 1.1.1.1. Это не DNS домашней сети. Canary содержит исправления для локальных имён и системного DNS. В Mihomo fake-ip-filter сам по себе не задаёт nameserver-policy для LAN. Проверки наличия ключей в JSON/YAML не доказывают разрешение printer.lan или корректный bootstrap имени VPN-узла при недоступном публичном UDP/53.

### 6. Surge/Loon/Quantumult X — пока только материалы для сборки

`rules/surge` содержит правила без политики, `rules/quantumultx` — фильтры с именами политик. Нет полного подключения узлов, DNS, итогового правила и настройки захвата. `docs/compatibility.md:44` это признаёт. Установка только этих списков не создаёт готовый VPN-профиль.

### 7. Автовыбор узлов и выдача панелью не доказаны для каждого клиента

Stable Stash — select, stable/canary sing-box — selector. Experimental sing-box — URLTest, но настоящая инъекция Remnawave не проверена. Shadowrocket/Happ/INCY зависят от приложения. Xray не имеет balancer. Количество узлов не следует ограничивать: проверять 0, 1 и несколько, обновления и удаление текущего узла.

Stable Mihomo допускает ручной DIRECT и сохраняет выбор. Это сознательный пользовательский выбор, а не доказанная автоматическая утечка; выбранный новый контракт требует убрать его из группы обязательного PROXY.

## Кандидаты, требующие runtime-подтверждения

1. **Mihomo/Stash hostname против IP:** blocked-IP `no-resolve` может быть пропущен до позднего разрешающего GEOIP RU. Canary с ru-ips/no-resolve может не распознать RU IP у неизвестного .com. Проверять hostname и тот же адрес отдельно, с fake-IP и HTTP CONNECT.
2. **Sing-box fake-IP:** порядок IP-списков не доказывает наличие реального IP на момент проверки. Нужен контролируемый DNS и выбор реального outbound; автоматически считать это подтверждённой утечкой нельзя.
3. **Холодный старт:** canary Mihomo скачивает правила через Garasu Auto. При пустом кэше и отказе узлов нужно установить, прерывается ли запуск или остаются общие DIRECT-правила без исключений. Текущие тесты заменяют providers локальными файлами.
4. **Полный отказ прокси:** текущий failover-тест использует .invalid. Ошибочная прямая попытка тоже может закончиться ошибкой DNS. Нужен доступный контрольный DIRECT-сервер и доказательство отсутствия обращений к нему, а не только код ошибки клиента.
5. **UDP/IPv6:** синтетические HTTP-узлы имеют udp:false. ipv6:false в ядре не доказывает отсутствие обхода через IPv6 ОС. Требуются реальные проверки UDP, QUIC/голоса и native IPv6 с включённым VPN.

## Источники и их назначение

Прочитаны актуальные доступные страницы/списки 3 ноября 2026. Файлы исследования сохранены вне репозитория: `/workspace/garasu-research`. Прямого измерения фильтрации из РФ не было.

- [DigneZzZ/routing](https://github.com/DigneZzZ/routing): существующая база Garasu. README объясняет, что refilter-domain — сокращённый набор исключений, пересекающихся с DIRECT, а не весь реестр. Он полезен именно вместе с default PROXY. Нельзя менять область DIRECT, предполагая неизменную полноту сокращённого набора.
- [Re:filter](https://github.com/1andrevich/Re-filter-lists): фильтрованные домены/IP и отдельные community-списки сервисов, ограничивающих российские адреса. Реестр и ограничения владельцев сайтов — разные источники.
- [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains): разделяет Block, GeoBlock и сервисные наборы. [GeoBlock](https://github.com/itdoginfo/allow-domains/blob/main/Categories/geoblock.lst) даёт независимую проверку DIRECT-исключений. README отдельно предупреждает, что геоклассификация зарубежных серверов сервисами может отличаться от физического размещения.
- [net4people/bbs](https://github.com/net4people/bbs): площадка для исследований и измерений цензуры; отдельные сообщения требуют проверки и не являются гарантированным списком работающих настроек.
- [eGames reverse proxy](https://github.com/eGamesAPI/remnawave-reverse-proxy): установка панели/узлов/страницы подписки, отдельные механизмы server routing и client balancer. Наличие установки не раскрывает настройки конкретной панели.

Недоступный `DigneZzZ/routing-build/main/README.md` вернул 404; его содержимое не использовалось. Изменение сетевого allowlist не потребовалось. Токены и персональные подписки не запрашивались.

Нельзя вывести достоверный текущий статус блокировки всех сервисов из одних списков. Различать: DNS-подмену, фильтрацию IP/SNI/протокола/транспорта у провайдера, геоотказ сервиса, ограничения аккаунта и репутацию выходного IP. Правило PROXY выбирает путь; оно не делает заблокированный VPN-узел доступным и не меняет страну аккаунта.

## Приёмка новой реализации

Одинаковый корпус решений для всех адаптеров: LAN, российский доступный домен, российский заблокированный домен, зарубежный домен, неизвестный .com на RU IP, российское имя на зарубежном CDN, IPv4/IPv6 literal, домен и IP с конфликтующими категориями, рекламное пересечение, DNS и адрес самого узла.

Повторить на холодном и тёплом кэше, при отказе источника правил/DNS/узла/всех узлов и после восстановления. Проверять выбранное правило и наблюдаемый выход; отдельно — обычное приложение через TUN и приложение через HTTP/SOCKS. Нативные импорты проверять на конкретных версиях клиентов и настоящем тестовом ответе Remnawave. Региональную доступность проверять хотя бы в домашней и мобильной сети пользователя.
