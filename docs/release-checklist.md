# Контрольный лист выпуска Garasu

**Публикация публичных файлов GitHub и изменение живого Remnawave — отдельные операции.**

Клиентам выпускается **одна** политика `policy/universal.json` и **один** SSR `release/remnawave/srr.json`. Автоматические тесты не создают отдельный профиль.

## Разработка в dev

- [ ] Включены последние изменения из main; история сохранена.
- [ ] Источники проверены, ревизия зафиксирована, лицензии/условия перепубликации учтены.
- [ ] Пересобраны MRS при изменении исходных доменов и CIDR.
- [ ] Синхронизированы 20 файлов удалённых rule-set с единой политикой.
- [ ] Перепроверены отчёты reports/routing-coverage.* и reports/geodata-integrity.* при изменении категорий или порядка правил.
- [ ] Проверены приоритеты REJECT / PROXY / DIRECT.
- [ ] Сохранены существующие URL клиентов из clients/ и install/.
- [ ] SSR не ссылается на отсутствующие активные шаблоны.
- [ ] Нет GitHub Actions, приватных ключей, токенов и персональных подписок.

## Офлайн-контроль

```bash
python3 scripts/qa.py --branch main
python3 scripts/qa.py --branch main --core /path/to/mihomo
```

Вторая проверка требует установленного Mihomo и обязательна при изменениях MRS/Mihomo. Ошибка на любом шаге блокирует выпуск. Синтетические узлы **не доказывают доступность реальных VPN-серверов**.

## Публикация в main

- [ ] Перенести прошедшие тестирование изменения без переписывания истории Git.
- [ ] Проверить ссылки main/release/ и ветку, на которую они указывают.
- [ ] Повторно запустить офлайн-контроль на опубликованном main.
- [ ] После публикации сравнить GitHub Raw с checkout:

```bash
python3 scripts/probe_release_assets.py --branch main
```

Если GitHub Raw временно недоступен, отметить сетевую проверку непроверенной, а не успешной.

## Внедрение в Remnawave — НЕ часть GitHub-релиза

- [ ] Сохранить действующие SSR, шаблоны и распределение прав.
- [ ] Проверить тестовую подписку и нужный responseType.
- [ ] Проверить выдачу персональных узлов и ручной выбор в Mihomo.
- [ ] Отдельно проверить Stash, sing-box, INCY, Happ, Shadowrocket.
- [ ] Проверить откат, прежде чем применять изменения к платным пользователям.

## Откат

Сломанный GitHub-релиз откатывается новым коммитом, сохраняющим историю. Изменения Remnawave откатываются из резервной копии панели; откат GitHub-коммита сам по себе **не возвращает** старые шаблоны в панели.


## Проверка единого профиля перед продажей

- [ ] Убедиться, что universal содержит ровно одну политику, генератор и все семь результатов синхронизированы.
- [ ] Проверить, что зарубежные домены идут через PROXY, обычные RU идут напрямую, а заблокированные RU исключения проверяются раньше DIRECT и реально загружаются или находятся в кэше при холодном запуске.
- [ ] Проверить прямой доступ к российским банкам, Госуслугам, маркетплейсам в используемых клиентских приложениях.
- [ ] Проверить импорт и маршруты в Stash, sing-box, Shadowrocket, INCY, Happ и Xray на поддерживаемых ОС.
- [ ] Проверить реальную выдачу шаблонов Remnawave на отдельном тестовом пользователе, затем миграцию без затрагивания платных клиентов.

- [ ] Не отмечать продукт готовым к массовой продаже без реальных E2E-тестов по используемым операторам/системам.
