# Native routing candidates

These are offline integration instructions. Shadowrocket, Happ, INCY, Surge,
Loon, and Quantumult X import and VPN behavior still require tests on the
actual app and OS version before a production rollout. Keep each user's
Remnawave subscription: Garasu supplies routing rules, not VPN nodes.

## Common rule order

Use the resources in this order. The URL prefix for every list below is
`https://raw.githubusercontent.com/togahimoko/garasu/main/rules/`.

| Order | Category | Action |
| --- | --- | --- |
| 1 | Local names and LAN/private IPs | DIRECT |
| 2 | `rkn-domains`, `rkn-ips`, `youtube`, `discord`, `ai`, `crypto`, `proxy`, `proxy-ips` | Personal VPN policy |
| 3 | `ads` | REJECT, if supported |
| 4 | Russian suffixes (`ru`, `su`, `moscow`, `xn--p1ai`, `xn--p1acf`, `xn--80asehdb`, `xn--c1avg`, `xn--80aswg`, `xn--80adxhks`, `xn--d1acj3b`) | DIRECT |
| 5 | `ru-ips` | DIRECT |
| 6 | Final/unmatched | Personal VPN policy |

The upstream `games`, `direct`, and `direct-ips` categories include foreign
destinations. Do not bind them to DIRECT. Quantumult X exports label those
three resources PROXY to make old individual imports conservative; new
integration links omit them. `steampowered.com` therefore follows the final
VPN route. A blocked domain or IP must win over a Russian suffix or IP.

## Shadowrocket

Import the personal Remnawave nodes separately, then import the managed
`clients/shadowrocket.conf` routing config from `install/links.json`. Select
Config mode and activate the app's system VPN. The managed config requests
updates every six hours. Verify that PROXY resolves to the imported personal
nodes, and that an empty or failed node pool never changes FINAL to DIRECT.

## Happ and INCY

Use the `happ` and `incy` links in `install/links.json` or the optional
Remnawave `routing` and `autorouting` response headers. `scripts/build_srr.py`
generates an offline SRR candidate from an exported panel rule set; its test
mode only matches diagnostic User-Agents. Both JSON profiles keep only
`geosite:private`, `geosite:category-ru`, the generated
`geosite:garasu-ru` suffix category, `geoip:private`, and `geoip:ru` for
DIRECT. The generated `geosite:garasu-ads` category excludes every ad suffix
that overlaps a PROXY category, so the existing documented
`block-proxy-direct` order does not reject `ads.youtube.com`. It retains
non-overlapping ad blocking. Their global default is proxy. Confirm the
effective route generated by the app's bundled core after import, including
the GeoSite category import, rule precedence, and a failed node pool.

## Surge and Loon

`install/links.json` contains ten policy-independent `surge_rulesets` URLs.
The ordered [Surge example](../clients/surge-integration.example) and
[Loon example](../clients/loon-integration.example) show concrete `RULE-SET`
lines with a placeholder for a personal policy. They are snippets to merge
into an existing personal profile, not independently importable subscriptions.
The remote file lines are `DOMAIN-SUFFIX` or `IP-CIDR` rules without a policy.
In an existing profile, attach the eight exception resources to its personal
VPN policy, then `ads` to REJECT and `ru-ips` to DIRECT. Add local/LAN rules,
the Russian suffix rules, and a final VPN rule in the order above. Configure
the app's DNS bootstrap for node hostnames and LAN resolver for local names.
Activate the app's VPN/TUN mode separately. Set resource refresh to six hours
where supported. The profile syntax and behavior require an app import test;
these instructions are an integration candidate, not a validated config file.

## Quantumult X

The `quantumultx` link in `install/links.json` imports eleven ordered remote
filter resources. The force-policy values in that link are lowercase
`proxy`, `reject`, and `direct`; bind `proxy` to the personal Remnawave node
policy in the app. The `ru-tlds` remote filter follows blocked/ads filters
and precedes `ru-ips`, so Russian suffix priority does not depend on ordering
between the remote and local sections. Add local/LAN rules and a final VPN
rule in the live profile. Importing resources alone does not configure
nodes, DNS, a final rule, or the system VPN. Confirm ordered application of
the filters and a six-hour refresh in the installed app. The
[Quantumult X example](../clients/quantumultx-integration.example) shows the
intended remote and local filter lines with a personal policy placeholder.
Its LAN section precedence and `FINAL` spelling require native import
validation.
Remove any older imported Garasu filter that forces `games`, `direct`, or
`direct-ips` to `direct` before testing the new link.

## Release integrity

`install/links.json` records the SHA-256 of `install/manifest.json` and the
manifest URL. The manifest records SHA-256 and byte length for native
Shadowrocket, Happ, and INCY profiles, every generated rule, and GeoSite/GeoIP
files, including the derived Quantumult X RU suffix filter. Before importing
a new candidate, fetch the linked manifest, verify
its digest against the link metadata, then use `scripts/check_delivery.py`
with `--links install/links.json` to bind the local manifest to those links
and probe selected remote assets. The native apps do not verify
this manifest or switch all cached resources atomically; a mixed snapshot
is still possible during updates. Recheck the imported resources on device
after the six-hour refresh.

## Device acceptance

On each app/OS version, test a known blocked `.ru` domain, a blocked RU IP,
an ordinary `.ru` name, `steampowered.com`, an unknown foreign name, a local
resolver and node hostname. Repeat after a cold rule-cache start, DNS outage,
and all-nodes-down event. Check UDP/QUIC and IPv6 on the device and inspect
the effective rule/packet path; repository tests cannot establish those
behaviors or connectivity from Russian home/mobile networks.
