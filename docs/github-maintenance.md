# Поддержка GitHub-репозитория Garasu

## Обязательные практики

В проекте используются только две рабочие ветки: **main** — выпуск, **dev** — разработка и тестирование.

Проверка выполняется командой:

§§§bash
python3 scripts/qa.py --branch main --core /path/to/mihomo
§§§

GitHub Actions не используются: в репозитории отсутствуют файлы .github/workflows. Это не заменяет защиту ветки.

## Настройки в интерфейсе GitHub

Эти параметры нельзя включить простым коммитом в репозиторий. Для владельца:

1. В **Settings → Rules → Rulesets** создать защиту main, запрещающую force-push и удаление. При необходимости добавить обязательное ревью/PR без блокировки единственного сопровождающего.
2. Ограничить права записи и регулярно просматривать подключённые приложения, токены и deploy keys.
3. Убедиться, что **Issues** включены, если нужны шаблоны ошибок и предложений в .github/ISSUE_TEMPLATE.
4. Включить **Private vulnerability reporting**, если доступно, чтобы не раскрывать проблемы безопасности в публичных Issues.
5. Удалить старые ветки только после резервного копирования истории и проверки прямых ссылок на их файлы.

## Публичная страница

Описание и topics репозитория редактируются отдельно в GitHub. В README должны быть видны назначение проекта, поддерживаемые клиенты, источник правил, проверка качества и эксплуатационные ограничения.

В репозитории пока **не назначена лицензия для собственного кода**. Её не следует выбирать автоматически: данные и бинарники, полученные из сторонних наборов, могут иметь собственные права и условия использования. Решение о распространении и лицензировании принимает владелец после проверки [SOURCES.md](../SOURCES.md).

## Выпуск и откат

Работать по [чек-листу](release-checklist.md): изменения в dev, полный офлайн-тест, перенос в main, сверка HTTPS GitHub Raw и отдельная проверка любых изменений Remnawave. Отказ от GitHub Actions не запрещает выполнять проверки вручную или через локальный терминал.
