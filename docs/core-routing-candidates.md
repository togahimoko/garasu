# Core routing candidates (2026-11-03)

The Mihomo, Stash-compatible, sing-box 1.14, and Xray advanced templates use the same decision order: explicit LAN and node bootstrap, blocked/domain proxy exceptions, ads rejection, ordinary Russian suffix/IP direct, then proxy. Games and the full upstream `direct` and `direct-ips` categories no longer cause foreign direct routing in these templates. They remain published data and still need Task 4 adapter alignment. Rule providers retain the existing six-hour update interval and Remnawave node injection markers.

This repository contains candidate templates, not verified installations. The complete blocked lists were generated from a pinned source snapshot, but a cold client with missing or corrupt remote rules can still apply an RU suffix fallback; these clients have no tested atomic manifest gate. Keep the last valid cached bundle and require a successful import/download before relying on the RU fallback. A warm cache can also be stale. The static tests confirm route order, not how every client resolves a hostname before its IP rule. Mihomo 1.19.32 was probed with a local DNS responder: an unlisted .ru hostname resolving to a blocked IP changed from DIRECT to the blocked-IP PROXY rule after removing `no-resolve`. Xray 26.10.21 was probed through its SOCKS listener for RU IP, foreign IP, and public-hostname-to-private-IP cases; its combined domain/private-IP guard routes the latter to PROXY while local names and literal private IPs stay DIRECT. Native Stash still needs a controlled hostname-to-blocked-IP runtime check. Sing-box 1.14.2 was probed with synthetic DNS: a blocked IP behind an unlisted .ru hostname used PROXY; an ordinary .ru hostname used DIRECT while the synthetic node was down; a public hostname resolving to a private IP used PROXY; LAN names and literal private IPs used DIRECT. These probes used a test-only local DNS responder for both resolver tags. Production routes ordinary RU suffix lookups to the local resolver after domain exceptions, and routes other hostname lookups to a TLS resolver detoured through Remnawave; the latter transport has parser validation but no live proxy-DNS reachability test. A real Russian ISP and device are still needed to check current blocked exceptions, IPv6, UDP, and DNS outages.

Mihomo provides a local mixed proxy listener; system-wide capture depends on the host application's TUN/VPN setting and effective config. The Stash template is syntax-checked with Mihomo, but native Stash import, VPN activation, and an all-down pool require device testing. The sing-box templates declare TUN with `auto_route` and `strict_route`; parser checks do not prove OS packet capture. Xray advanced offers SOCKS/HTTP listeners only and needs an external VPN/TUN adapter for system-wide routing. The experimental sing-box URLTest group's real Remnawave injection remains unverified; the stable selector and synthetic injected-node fixtures do not establish panel behavior.
